# Reference data of the PMD module's tests

`tests/test_pmd.c` checks lrvne's PMD module (`include/lrvne/pmd.h`) against what the real
driver does with the same input.

## The input: ours

| file | what it is |
|---|---|
| `SYNTH1.M`, `SYNTH2.M`, `SYNTH3.M` | songs written byte by byte by `tools/lrvne/pmd.py` (`synth_songs`), in the format MC 4.7 compiles to; what each exercises is in its docstring |
| `SYNTH.SSG` | 14 SSG effects of our own, in the format of PMD's built-in table (`synth_ssg_table`) |

`python3 -I tools/lrvne pmd check tests/data/pmd` confirms the files are what the generator
writes (the tools' tests do this).

## The output: the real driver's

Each `*.log` is what PMD.COM 4.7g (MD5 `cd5634a197a3163734722da554ddadf8`, the 26K build)
did when it ran under an x86 emulator with a pretend PC-9801-26K board:
1. PMD.COM was installed with the options named in the log's first line.
2. With `SSG-effect table SYNTH.SSG` in the log's second line, the table PMD keeps at
   CS:2CE9h was replaced in memory with `SYNTH.SSG` before the song started. No byte of
   PMD.COM's own data is in these files.
3. The song was copied into PMD's music buffer and started (INT 60h AH=00h).
4. The two timers of the chip were run from their register values, and the interrupt handler
   was called at each overflow.

Every line is one of:

    # comment
    I r=v r=v ...       the installer's register writes (hex), in order
    S AX r=v ...        an INT 60h call with AX (hex) and its writes; S 0000 starts the song
    T CLOCK K s2=SS m=MMMM f=FF s1=SS r=v ...
                        a timer interrupt at master clock CLOCK (3 993 600 Hz, counted from
                        the installation); K = A, B or AB (both flags: B's work runs first);
                        status2, the measure counter, the fade volume and status1 after it;
                        then the writes of the interrupt, in order

An `S` line between two `T` lines was called between those interrupts.

| log | song | options | calls after the start |
|---|---|---|---|
| `synth1.log` | SYNTH1 | `/M10 /V0 /E4 /F /K` | none |
| `synth1-fade.log` | SYNTH1 | the same | AH=19h 40h before interrupt 300, AH=19h 00h before 900, AH=02h 14h before 1500 |
| `synth2.log` | SYNTH2 | the same | none |
| `synth3.log` | SYNTH3 | `/DF5 /K /M8 /V0 /E0`, table `SYNTH.SSG` | AH=03h 07h before 1200, AH=19h 60h before 2400, AH=19h 00h before 3000, AH=02h 10h before 4000 |

The logs are reference output and are not regenerated by the build: changing a song means
running the real driver again.

The same replay works for any song: `build/host/tests/test_pmd LOG SONG [SSG-TABLE]` replays
one log made the same way (for example from a game's own songs, with PMD's own SSG-effect
table, `tools/lrvne/pmd.py ssgtab`) and says whether every interrupt was the same.
